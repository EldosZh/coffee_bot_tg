# ☕ Coffee Time Almaty

Telegram-бот кофейни на Python 3.13, aiogram 3 и SQLite. Работает в существующем CoffeeShopBot: `python bot.py`.

## Возможности

- Пять категорий, 17 стартовых товаров, цены в тенге.
- Пошаговая настройка напитков: размер, температура, молоко, сироп, дополнительный эспрессо; количество 1–99. Еда без параметров напитка.
- Корзина в SQLite: до 20 разных позиций, количество, удаление, очистка, промокоды.
- Checkout FSM: получение, адрес, телефон (свой контакт или текст), комментарий, оплата, бонусы, подтверждение.
- История с составом и параметрами; повтор заказа по текущим ценам.
- Бонусы 5% от окончательной суммы, округление вниз; 1 бонус = 1 ₸. Списание до 30% суммы после промокода, не больше баланса.
- Профиль, изменение телефона, оценки 1–5 и отзывы в SQLite.
- `/admin`: заказы с пагинацией, статусы, уведомления, стоп-лист, цены, промокоды, статистика.
- Постоянная очередь уведомлений: временные ошибки повторяются, блокировка бота помечается как невозможность доставки. Администраторы должны сначала отправить боту `/start`.

Демонстрационные адрес и часы: проспект Абая, 00, 08:00–22:00. Перед реальным использованием замените адрес в `config.py`, часы в `handlers/start.py`. Стоимость и возможность доставки уточняет кофейня; бот не начисляет плату за доставку. Карта работает только в демо-режиме: подключения к банку и списания денег нет, заказ явно помечается как тестовый. Статистика включает демо-заказы и отражает оформленные суммы, а не банковские поступления.

## Установка в Windows (PowerShell)

Нужны Python 3.13 и доступ к Telegram API.

```powershell
cd "C:\Users\zhana\OneDrive\Рабочий стол\CoffeeShopBot"
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если `.env` существует, сохраните его. Только для новой установки скопируйте `.env.example` в `.env`.

```dotenv
BOT_TOKEN=PASTE_YOUR_BOT_TOKEN_HERE
ADMIN_IDS=123456789,987654321
SHOP_NAME=Coffee Time Almaty
```

Токен из BotFather храните только локально. `ADMIN_IDS` — числовые Telegram ID через запятую; пустое значение закрывает админку для всех. Бренд задан в `config.py`; старый `SHOP_NAME` оставлен для совместимости конфигурации и не меняет название.

```powershell
.\.venv\Scripts\python.exe bot.py
```

При активированной среде: `python bot.py`. Остановка Ctrl+C. Запускайте один процесс polling на токен. Если `python` открывает Microsoft Store, используйте прямой путь к интерпретатору или `.venv`.

В текущем окружении найден Python 3.13 по прямому пути; если `py -3.13` тоже не работает:

```powershell
& "$env:LOCALAPPDATA\Python\pythoncore-3.13-64\python.exe" bot.py
```

Этим же интерпретатором можно создать `.venv` через `-m venv .venv`.

## Команды и навигация

- `/start` — регистрация, главное меню, отмена ввода.
- `/cancel` — отмена ввода; корзина сохраняется.
- `/admin` — панель только для `ADMIN_IDS`.

Главная клавиатура: Меню, Корзина, Мои заказы, Профиль, Бонусы, Отзывы, О кофейне. «Назад» возвращает к предыдущему шагу. Клавиатура контакта появляется при запросе телефона.

Незавершённый FSM-ввод хранится в памяти: после перезапуска начните оформление из корзины заново. Корзины, пользователи, промокоды, заказы, бонусы, отзывы и очередь уведомлений сохраняются в SQLite.

## Инструкция администратора

1. Укажите ID в `ADMIN_IDS`, перезапустите бота, отправьте `/start`, затем `/admin`.
2. «Новые заказы» / «Все заказы» → заказ: клиент, телефон, состав, параметры, суммы, адрес, комментарий и оплата.
3. Статусы: Новый → Готовится → Готов → Завершён. Для доставки доступен «В пути» после «Готов». До завершения можно отменить. Клиент получает уведомление через очередь. Завершённые и отменённые заказы терминальны.
4. Отмена восстанавливает списанные бонусы и убирает начисление. Если начисленные бонусы уже потрачены и баланс недостаточен, отмена требует ручной сверки и блокируется с понятным сообщением. Использование промокода при отмене не освобождается.
5. «Товары» → товар → стоп-лист или новая целочисленная цена. Корзины пересчитываются; если цена меняется после подтверждения, нужно новое оформление. Цены оформленных заказов неизменны.
6. «Промокоды» → «Создать / изменить»: `SUMMER10 10 1 2027-06-30 100 1`. Формат: код, процент, активен 1/0, дата окончания включительно по Алматы, общий лимит, лимит на клиента. `-` вместо даты или общего лимита — без ограничения. Повторная запись обновляет настройки, сохраняя использования. Для отключения запишите код с активностью `0`.
7. Стартовые WELCOME10 (10%, 1000 использований) и COFFEE15 (15%, 500 использований) — по одному разу на клиента. Лимиты проверяются и расходуются транзакционно при создании заказа.
8. «Статистика»: заказы, выручка, средний чек, пользователи и популярный товар. Выручка, средний чек и популярность исключают отменённые заказы. «Сегодня» считается по UTC+5.

## База и миграция

`coffee.db` находится рядом с `bot.py`, независимо от папки запуска. При первом запуске создаются таблицы и seed. Повторный запуск не сбрасывает цены, стоп-лист и промокоды.

Старая база копируется в `coffee.db.pre-mvp.bak` перед миграцией. Старые таблицы сохраняются как `legacy_users`, `legacy_cart`, `legacy_orders`. Переносятся ID заказов, пользователи, бонусы, корзины и история. Состав старых заказов прежний бот не записывал: карточка сообщает об этом, повтор предлагает выбрать товары в меню. Дата регистрации старых пользователей — дата миграции. Их баланс принят за исходную сумму начислений: исторический объём начислений прежний бот не сохранял.

Заказ атомарен: позиции, промокод, бонусы, очистка корзины и очередь уведомлений записываются одной транзакцией. Ключ подтверждения защищает от повторного создания заказа. Изменение корзины, наличия или суммы после экрана подтверждения требует нового оформления. На рабочих соединениях включены foreign keys.

Не добавляйте `.env`, базу, резервные копии и journal/WAL-файлы в Git — исключения есть в `.gitignore`. Перед обновлением делайте отдельную резервную копию. Для отката остановите бота и восстановите резервную копию вместе с соответствующей версией кода.

## Структура

```text
bot.py                 запуск, dispatcher, middleware
config.py              .env и настройки
database/
  db.py                хранилище, транзакции, миграция
  models.py            схема и статусы
  seed.py              меню и промокоды
handlers/
  common.py            вывод, проверки, middleware
  start.py catalog.py cart.py checkout.py
  orders.py profile.py reviews.py admin.py
keyboards/             reply.py, inline.py
services/              pricing.py, bonuses.py, notifications.py
tests/                 проверки без сети на временных базах
```

## Проверка

```powershell
.\.venv\Scripts\python.exe -m compileall -q bot.py config.py database handlers keyboards services tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe bot.py --check
```

Тесты используют временные базы. `--check` проверяет импорты, роутеры и инициализацию рабочей базы, включая миграцию, без обращения к Telegram. Реальное соединение проверяется запуском `bot.py` и заказом в Telegram. Данные банковской карты бот не собирает.
